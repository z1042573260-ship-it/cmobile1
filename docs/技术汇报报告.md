## 一、项目概述

### 1.1 项目背景

建筑工程项目（厂房、住宅、园区、市政等）是通信基础设施建设的核心需求源头。项目从立项、规划到施工的每个阶段，都产生基站选址、室内分布系统（室分）、专线、物联网等通信业务机会。然而：

- **信息来源分散**：政府公告、招标网站、新闻媒体等十余个信息源，人工跟踪效率极低
- **信息价值密度低**：大量流程性公告（废标、更正、结果公示等）混杂其中，需人工筛选
- **时效要求高**：施工阶段介入窗口短，错过"抢建"窗口即失去商机
- **地理定位难**：项目名称与具体位置的对应关系需要人工逐个核实

本项目构建了一套**从信息采集到可视化决策**的完整自动化系统，实现对烟台地区大型建设工程项目的**实时监测、AI 深度分析、地理位置可视化预警**。

### 1.2 项目目标

| 目标 | 实现方式 |
|------|---------|
| 全自动信息采集 | 7 个爬虫每周增量抓取政府官网，自动去重入库 |
| AI 深度情报分析 | 大模型一次调用输出基站技术评估 + B2B 商机情报（30+ 字段） |
| 地理可视化预警 | 3D 地图大屏 + 2D 卫星地图定位，红/黄预警直观呈现 |
| 决策报告输出 | 周报 Excel + 邮件自动推送，领导一目了然 |

### 1.3 系统全景

## 二、大屏系统技术报告（3D 可视化）

### 2.1 技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 渲染引擎 | Three.js（WebGL） | 3D 地图主体，烟台 13 区县挤出体（ExtrudeMap） |
| 动画引擎 | GSAP | 柱状图生长动画、下钻/返回缩放过渡 |
| 图表库 | ECharts 5 | 区县预警数据、项目类型/阶段饼图、时间趋势 |
| 地图瓦片 | 高德街道瓦片（Web Mercator XYZ） | 无需 API Key，raw 瓦片 CORS 直连 |
| 2D 地图 | Leaflet + 高德瓦片 | 街道级定位、自由平移缩放 |
| 数据驱动 | dashboard_data.json（MySQL 导出） | 5 分钟自动轮询检测更新 |

### 2.2 核心功能

#### 2.2.1 三模式可视化（模式切换联动）

| 模式 | 呈现 | 数据口径 |
|------|------|---------|
| **柱状图** | 各区县项目数 3D 柱（生长动画 + CSS3D 标签） | 周期筛选联动 |
| **热力图** | 街道瓦片窗口 + 密度可视化 | 周期筛选联动 |
| **预警图** | 3D 图钉（倒水滴 + 地面扩散光圈 + 悬浮标签） | 周期筛选联动 |

**图钉交互细节**：同坐标去重（0.0001° 内折叠）、点击屏幕距离判定（44px 阈值，比 3D 射线稳定）、下钻时图钉跟随区县 GSAP 同步放大（Box3 世界中心精确对齐）、返回时恢复后再淡入。

#### 2.2.2 高德街道瓦片引擎（核心技术点）

- **无需 Key**：直接拉取高德公开 raw 瓦片（webrd0{1-4}.is.autonavi.com），CORS `*`
- **动态加载**：城市总览（视野远）用静态高清图（1 次请求零延迟）；贴近时按相机视野切实时瓦片，放大自动换更清晰层级（z 上限 15），防抖 200ms
- **精确对齐**：瓦片画布按实际瓦片网格地理范围（`imgRange`）定位，与 3D 区县边界严格对齐（曾修复 5% 拉伸错位 bug）
- **兜底**：瓦片失败自动回退静态图

#### 2.2.3 周期筛选（第一优先级联动）

本周 / 本月 / 今年 三档按钮，作为**第一优先级**统一作用于所有视图：
- 3D 柱状图（柱高/柱顶数字）
- 3D 预警图钉（严格过滤，无日期记录一律排除）
- 2D 地图标记
- 左栏项目列表、实时统计卡片
- 时间趋势、类型/阶段饼图
- 下钻区县和 2D 往返全程保持筛选状态

**技术要点**：统一 `periodStartStr()` 计算窗口起点（week=今天-7 / month=本月1号 / year=1月1日），所有过滤点共用同一函数，保证口径一致（曾修复"统计排除但图钉保留"的口径不一致 bug）。

#### 2.2.4 区县下钻与 2D 往返

- 点击区县 → GSAP 同步放大（3D 板块 + 街道贴图 + 图钉）→ 该区县项目明细
- "详情" → 切换到 2D 高德地图，`flyTo(z16)` 街道级定位
- 返回 3D：**相机/目标/下钻状态精确恢复**（进入 2D 前捕获，返回时恢复）

#### 2.2.5 数据自动刷新

- 后端链路跑完自动导出 dashboard_data.json（含 `updated_at` 时间戳）
- 前端每 5 分钟轮询检测更新（cache-buster 防缓存）→ 检测到变化自动 `refreshAllCharts()` + `reloadPoints()`（重建图钉，不闪屏）

### 2.3 关键 Bug 修复经验（体现工程严谨性）

| Bug | 根因 | 修复 |
|-----|------|------|
| 贴图不显示（高度塌缩） | 投影 Y 轴未取反，`h` 为负被 Math.max 塌成 1e-6 | Y 轴取反对齐地图 + 修正符号 |
| 瓦片与地图错位 5% | 画布覆盖"网格取整范围" vs 平面覆盖"可见范围"，aspect 不一致 | 返回实际瓦片范围 `imgRange` 精确定位 |
| 柱状图标签间歇消失 | CSS3DRenderer 视锥剔除 + 重建对象 | updateBars 复用 CSS3D 对象 |
| 下钻图钉偏移 | Box3 世界中心误用 y（高度）做地理轴缩放 | 用 `center.z=geoY` + 本地 y 缩放公式 |
| 旋转光环变形 | 更新光辉面时误改方形光环 | width!==height 判断区分 |

## 三、report2 数据分析报告技术报告

### 3.1 定位与设计

report2 是**面向领导决策的数据分析报告页**：数据全量真实（无假数据）、多维度筛选、透视统计、一键导出、邮件周报推送。

### 3.2 数据源体系（三级回退）

```
1. /api/report-data  ← Flask 数据库实时数据（登录保护）
2. data/report_data.json ← 管线自动导出（全量）
3. data/dashboard_data.json ← 兜底
```

### 3.3 多维度叠加筛选体系

| 维度 | 选项 | 说明 |
|------|------|------|
| 区县 | 全部 / 具体区县 | 叠加筛选（AND 关系） |
| 预警级别 | 红 / 黄 | 与所有维度叠加 |
| 时间 | **本周**（默认）/ 全部月份 / 具体月份 | 本周口径：今天-7 天 |
| 阶段 | 5 类标准阶段 | 规划/招标/施工/竣工/待核实 |
| 类型 | 13+ 类项目类型 | 从数据动态收集 |
| 搜索 | 关键词 | 标题/区县/类型/阶段/AI摘要 |

**联动范围**：项目明细列表、区县柱状图、统计卡片（本周口径 + 较上周对比）、导出 Excel 全部随筛选联动。

### 3.4 统计口径设计（关键逻辑）

- **统计卡片**：项目总数/红色预警/黄色预警 = **本周口径**（今天-7 天）
- **趋势对比**：**较上周**（本周 [今天-7, 今天] vs 上周 [今天-14, 今天-7)），显示"较上周 ↑/↓ N"或"持平"
- **月度趋势图**：全年全量（不受本周默认筛选影响），点击月份节点可下钻筛选该月
- **无日期记录**：折线图并入当前月（不显示"未知"节点），统计严格排除

### 3.5 Excel 导出（数据透视体系）

前端 exceljs 生成 **4 sheet** Excel：

| Sheet | 内容 |
|-------|------|
| 项目明细 | 当前筛选结果 12 列（带自动筛选） |
| 区县×类型透视 | 交叉统计（行区县 × 列类型，含合计） |
| 区县×预警透视 | 交叉统计（含合计） |
| 区县柱状图 | ECharts 当前图表 PNG 图片 |

所有 sheet 带 Excel 原生自动筛选（`!autofilter`），"打开即用"。

### 3.6 邮件周报自动推送

| 组件 | 内容 |
|------|------|
| 邮件主题 | 建筑预警工程信息周报 - 日期 |
| 正文 | 蓝头卡片 + 报告周期 + **4 格核心指标**（本周项目/红/黄/覆盖区县）+ **HTML 横向条形图**（区县分布，邮件客户端兼容）+ 附件说明 |
| 附件1 | 周报 Excel：**概览区**（标题/周期/统计）+ 本周项目明细 + 区县汇总 sheet |
| 附件2 | 报告 HTML（report2.html 完整页面，内嵌数据离线可用） |

**HTML 条形图技术点**：邮件客户端（Outlook/QQ 邮箱）对 CSS 支持有限，采用**表格 + div 宽度百分比**实现横向条形图，100% 客户端兼容（曾修复竖排 inline-block 在邮件中被截断的问题）。

## 四、数据链路技术报告（自动化核心）

### 4.1 爬虫系统

| 爬虫 | 数据源 | 特点 |
|------|--------|------|
| yantai_districts | 烟台 13 区县政府公告 | 大汉 JCMS CMS API 分页，4 种 HTML 变体解析 |
| yantai_bidding | 公共资源交易网 | 招标/中标公告 |
| yantai_planning | 自然资源和规划局 | 规划许可公示 |
| yantai_investment | 投资促进中心 | 招商项目 |
| shm_news | 上海建工新闻 | 公司项目动态 |
| shandong_transport / zbxx | 省交通运输厅 / 省招标 | 省级工程信息 |

**工程化特性**：
- **每周增量**：`SEARCH_DAYS=7` 统一窗口（cutoff = 今天-7），首次全量可切 START_DATE 绝对日期
- **自动去重**：title + source 唯一校验，重复跳过
- **失败自愈**：网络重试（指数退避）、CMS 参数自愈（从页面 queryData 正则提取）、区县失败隔离休息、单爬虫异常不影响整条链路
- **数据质量**：三层相关性评分（流程公告过滤 → 标题加权 → 详情页内容分析）

#### 4.1.1 数据维度设定（爬什么、怎么爬）

**维度一：数据源维度（覆盖完整性）**

| 数据源 | 覆盖类型 | 获取方式 |
|--------|---------|---------|
| 13 区县政府公告 | 行政审批/规划许可/批后公布 | 大汉 JCMS CMS API（分页接口 + 4 种 HTML 列表变体解析） |
| 公共资源交易网 | 施工招标/中标公示 | 交易 API（按时间窗口查询） |
| 规划局 | 用地/规划/工程许可 | 列表页翻页 |
| 投资促进中心 | 招商项目 | 列表页 |
| 建工新闻 | 公司项目动态 | 新闻列表 |
| 省交通厅/省招标 | 省级工程 | API + 列表 |

**维度二：时间维度（增量窗口）**
- 统一 `SEARCH_DAYS = 7`：每次只爬最近 7 天公告（cutoff = 今天 - 7）
- 翻页**早停策略**：发现列表日期早于 cutoff 立即停止翻页（旧公告不会再新，节省请求）；晚于 END_DATE 的跳过
- 区县粒度早停优化：连续 3 页不动产类公告占比 ≥95% 提前终止（如龙口不动产集中发布场景）

**维度三：地理维度（区县归属）**
- 13 区县独立配置（域名、栏目 col、HTML 变体 A/B/C/D），区县失败互不影响
- 详情页补充提取：列表无日期的区县（龙口）从详情页 `span.time` 提取（修复换行符拆分问题）

#### 4.1.2 相关性评判依据（三层评分引擎）

这是"信息价值密度低"问题的核心解法——**不是所有公告都值得分析**，用三层过滤体系量化每条公告的工程价值：

```
Layer 0: 流程公告过滤（硬性剔除）
Layer 1: 标题加权评分（-5 ~ +5 量化）
Layer 2: 详情页内容分析（规模/投资/性质提取）
```

**Layer 0 — 流程公告过滤**（先剔除无效公告）

| 类型 | 关键词 | 处理 |
|------|--------|------|
| 流程性公告 | 更正 / 废标 / 流标 / 终止 / 澄清 | 直接剔除（非新建工程） |
| 结果公示类 | 中标结果 / 成交结果 | 直接剔除（流程尾声） |
| "变更"特例 | 仅"招标变更/采购变更/中标变更"组合词 | 精确匹配，避免误伤"建设工程规划许可证变更批后公布"（有效公告） |

**Layer 1 — 标题加权评分**（每条公告得一个工程价值分）

| 信号类型 | 示例 | 分值 |
|---------|------|------|
| 强正向（大工程） | 施工总承包、产业园、开工、建设规模 | +5 ~ +3 |
| 正向（工程类） | 规划许可、用地预审、设计施工 | +2 ~ +1 |
| 规模信号 | 亿元、万㎡、公里、户 | +3 ~ +1 |
| 负向（非工程） | 设备采购、法律服务、绿化养护、办公用品 | -5 ~ -1 |

> 设计思路：**标题即公告的核心语义**，词频加权能低成本快速区分"要建的工程"和"流程动作"。

**Layer 2 — 详情页内容分析**（深挖工程实质）

| 提取字段 | 说明 |
|---------|------|
| 规模 | 建筑面积/用地面积/建设内容（㎡、亩、栋数） |
| 投资额 | 亿元/万元（决定工程级别） |
| 区县 | 从正文确认真实区县归属 |
| 项目性质 | 新建 / 扩建 / 改造（扩建改造是增量商机） |

**最终输出**：每条记录带 `relevance_score`（综合分）→ 高分进入 AI 分析，低分直接淘汰，保证 AI 算力花在高价值信息上。

### 4.2 AI 统一情报分析管线

**一次大模型调用，输出 30+ 字段**（基站评估 + 商机情报双维度）：

| 维度 | 关键字段 |
|------|---------|
| 项目本质 | project_name / project_type（13 类枚举铁律）/ district / scale / investment / developer / status（5 类阶段） |
| 基站评估 | need_base_station（高/中/低）/ base_station_type（宏站/室分/小站）/ coverage_area |
| 商机情报 | warning_level（红/黄/无）/ priority（1-5⭐）/ score / telecom_needs / ai_summary / 跟进建议 |

**技术要点**：
- **温度 0.0 + 枚举铁律**：类型/阶段/区县强制白名单约束（烟台标准区县，禁止编造）
- **三步推理**：项目本质理解 → 基站技术评估（从通信原理：钢结构屏蔽→室分，高层→宏站+室分）→ 商机判断
- **失败重试**：断网/限流/超时自动重试 3 次（60s 间隔），关键信息不丢失
- **限流自适应**：账户级 RPM≈1/分钟 → 相邻请求间隔强制 ≥60s（节流补足），429 指数退避（10/20/40/80s）

#### 4.2.1 提示词工程设计（Prompt Engineering）

**角色设定**：20 年经验的通信基础设施情报分析师（基站选址 + 政企 B2B 销售 + 工程评估专家），核心任务是"全景式情报分析"，一次性输出【基站技术评估】+【商机销售情报】两个维度。

**数据源信任原则**：输入信息来自政府官网爬虫（权威一手数据源）——信任公告中的项目名称、建设方、地点、规模等事实，基于公告类型（规划许可/招标公告/施工许可/批后公布）推断项目阶段。

**主动运用领域知识**（不依赖外部搜索也能推理）：
- 各类工程（住宅/商业/市政/交通/工业/教育/医疗/科研）的通信需求特征
- 基站选址规范：宏站覆盖半径 300-500m、室分系统部署条件（地下室/高层/大型封闭空间）、小站适用场景
- 通信运营商政企产品体系：专线、物联网、云服务、固话、视频会议、IDC
- 建设工程全生命周期：立项审批→规划设计→招投标→施工→竣工，各阶段通信需求切入点

**四步工作流**（在 System Prompt 中结构化约束）：

```
① 快速分流：判断是否"跳过"类型（征地补偿/听证会/养护/管道改造/友商业务/流程公告/门卫等）
   → 是：直接返回 {"warning_level":"无预警","skip":true} 立即停止
② 外部验证（联网搜索，仅为本条公告补全证据）：
   - 竣工阶段判断（宏站抢建口径）：
     项目一旦进入"主体竣工/验收/交付" → 施工期抢建窗口关闭 → 直接判无预警
   - 计划工期校验（防过时红色）：施工许可证有效期限已过期 → 联网核实实际进展
     · 仍在施工（延期）→ 维持原级；已竣工 → 无预警；无证据 → 按原定日期执行
   - 补全证据：搜索项目招标/施工/投资/建设方/精确地址
③ 三步深度分析（核心推理）：
   - 项目本质理解 → 类型/规模/建设方/阶段
   - 基站技术评估 → 从通信原理出发（钢结构→屏蔽→室分 etc.）
   - 商机情报分析 → 建设方价值 + 具体需求 + 跟进时机
④ 输出：直接返回 JSON（30+ 字段），不确定实体填"待核实"，禁止编造
```

#### 4.2.2 字段体系与枚举约束（30+ 字段一次输出）

| 分组 | 字段 | 约束 |
|------|------|------|
| 项目本质 | project_name / project_type / district / location / scale / investment / developer | **project_type 13 类枚举铁律**：工业厂房/仓储物流/住宅小区/商业综合体/学校/医院/工业园区/市政设施/交通工程/能源电力/科研设施/景区文旅/其他 |
| 阶段 | status | **5 类阶段枚举**：规划阶段/招标阶段/施工阶段/已竣工完工/待核实 |
| 基站评估 | need_base_station（高/中/低）/ base_station_type（宏站/室分/小站/组合）/ coverage_area | 从通信原理推断（地下室→室分，高层→宏站+室分，园区→宏站） |
| 商机情报 | warning_level（红色/黄色/无预警）/ priority（1-5⭐）/ score / telecom_needs（具体到"冷库专用室分（防潮防低温型）"）/ ai_summary | 预警 = 商机价值 × 跟进时机 |
| 元数据 | source_url / source_name / publish_date | Python 侧回填，AI 不可篡改 |

**区县白名单注入**：运行时将烟台标准区县白名单注入 System Prompt（"district 必须且只能是以下之一，无法确认填'待核实'"），从源头杜绝编造区县。

#### 4.2.3 结果清洗与归并（数据可信度保障）

**清洗规则（_clean_unified_result）**：
- 经纬度合法性校验：±180 / ±90 范围，非法移除
- 区县白名单校验：不在白名单 → 标记"待核实"（不编造）
- 字段类型强制（int/float/bool）

**项目实体归并（merge_projects）**：同一项目的多条公告（如"规划许可 + 招标公告"）按 project_name 归并为一个情报记录：
- 同组取最高预警等级 / 最高优先级 / 最高评分
- 通信需求合并去重
- 多条公告 URL 合并（完整证据链）
- 归并组记录全部原始记录 ID → 批量标记已处理（防重复分析）

### 4.3 经纬度体系（精确定位保障）

大屏每个预警点必须落到真实街道级位置，定位错误会导致预警信息混乱。因此经纬度不采用"AI 猜测"，而是**独立的地理编码子系统**严格把关：

```
AI 输出 location/项目名（地址描述）
  → 第一级编码：location + 区县 → 高德地理编码 API（GCJ-02）
  → 精度闸门：返回"省/市/城市/区县"级（行政中心）→ 拒绝
  → 第二级编码：项目名 + 区县 → 高德重试
  → 区县匹配校验（region_ok）
  → 命中才写入 lng/lat（6 位小数）
  → 仍缺坐标 → 不入库（保持待重试，大屏定位不丢）
```

**① 坐标系与精度**：GCJ-02（高德/腾讯原生加密坐标系），十进制 6 位小数（≈0.1 米精度），与大屏/2D 地图坐标系完全一致，无需偏移转换。

**② 两级编码策略**：优先用 AI 提取的 `location`（如"高尔夫东路西、海核路北"）编码；location 缺失/查不到时降级用项目名（如"万华化学绿电产业园三期"）编码——项目名常能直接命中园区/企业 POI。

**③ 精度闸门（硬约束）**：高德返回结果的 `level` 为 省/市/城市/区县（即退回行政中心/中心点）时，**严禁直接采用**——"莱山区"的区县中心坐标会让预警点全部堆在地图中心，无法定位到真实街道。必须进入二次解压流程。

**④ 区县匹配校验（region_ok）**：高德返回的 district 必须与记录区县精确匹配（防止跨区错配，如海阳项目被匹配到福山）；功能区兼容（高新区/开发区是功能区，高德返回其所属真实区县莱山/福山/蓬莱，仍视为命中）。

**⑤ 二次解压（中心兜底记录的精细化）**：对第一遍仍退化成"区县中心点"的记录，逐条**联网搜索公示原文地址** → 提取真实道路/村/门牌 → 高德重编码 + 同步更新笼统 location（如"烟台市 莱山区"→"莱山区观海路以西、双河东路及学院西路以北"）。

**⑥ 入库闸门**：最终仍缺坐标的记录**不入库**（保持未处理状态，下次管线重试补全）——宁可等待也不让大屏出现无法定位的预警点。

### 4.4 自动入库与增量管道

```
爬虫 → raw_projects（原始表，processed=False）
  → collect_from_db 汇总未处理记录
  → AI 分析（成功才入库）
  → 坐标补全（高德编码 + POI + 网页搜索）
  → upsert projects 表（按 project_name 唯一键）
    · 新增：INSERT；已存在：仅更新有值字段（NULL 不覆盖已有）
    · 缺坐标 → 跳过入库（不丢定位信息）
  → 标记 raw_projects 已处理（防重复分析）
  → 自动导出大屏数据 + 报告数据
```

**"无预警不入库"（管线设计，双保险）**：
- **Prompt 级**：lng/lat 字段描述要求"仅红/黄预警补充坐标"——AI 对无预警记录不输出坐标 → 天然缺坐标
- **入库闸门级**：缺坐标 → SKIP（新项目）

两道关卡叠加，**无预警记录永远不会进入 projects 表**（大屏只展示红/黄预警，流程公告/无价值公告被拦截在 AI 分析层与入库层）；无预警记录仍会被标记 processed（不重复分析，但不入库）。

### 4.5 数据一致性保障

- **MySQL**：本地 MySQL（yantai_projects 库），projects 表 37 字段全量管理
- **幂等 upsert**：144 条重跑验证 0 新增全更新（值无变化不写）
- **NaN 防线**：AI 返回 NaN 坐标/数值 → 置 NULL 或跳过，禁止 NaN 入库（pymysql 会拒绝）

## 六、亮点总结（汇报金句）

1. **全自动闭环**：从政府公告到领导邮箱，全程无人值守——爬虫采集 → AI 分析 → 自动入库 → 大屏/报告/邮件自动更新
2. **AI 深度推理**：不是简单的关键词匹配，而是从通信原理出发的技术评估（钢结构厂房→室分覆盖、园区→宏站），30+ 字段一次输出
3. **定位精确性**：高德地理编码 + 精度闸门（拒绝行政中心坐标）+ 区县匹配校验，保证大屏每个预警点真实可定位
4. **决策友好**：周报 4 格核心指标 + 区县分布图 + 透视 Excel，"打开即用、一目了然"
5. **工程可靠性**：失败重试、限流自适应、增量管道防重复、NaN 防线——自动化系统能长期无人值守运行
6. **数据真实**：全链路无假数据，所有展示内容均来自政府官网 → AI 分析 → 数据库
